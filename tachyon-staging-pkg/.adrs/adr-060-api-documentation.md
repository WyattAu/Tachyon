# ADR-060: Automated API Documentation Generation

## Status
**Accepted**

## Context
The Tachyon project exposes multiple API surfaces (REST, WebSocket, IPC, CLI). Manual API documentation maintenance is error-prone and leads to outdated documentation. We need automated generation to ensure consistency and accuracy.

## Decision
Implement automated API documentation generation using Rust macros, OpenAPI specifications, and TypeScript type definitions.

## Consequences
### Positive
- Documentation always in sync with code
- Multi-format output (OpenAPI, Markdown, TypeScript types)
- Reduced maintenance overhead
- Single source of truth for API contracts

### Negative
- Requires careful annotation discipline
- Additional build time for doc generation
- Need for macro/tooling maintenance
- Initial learning curve for developers

## Alternatives Considered
1. **Hand-written Documentation**
   - Pros: Full control, no tooling dependency
   - Cons: High maintenance burden, prone to drift, manual synchronization
   
2. **Third-party Documentation Tools**
   - Pros: Established solutions
   - Cons: May not integrate with build system, limited customization

3. **Runtime Documentation Generation**
   - Pros: Always up-to-date
   - Cons: Performance overhead, runtime dependencies

## Implementation Details
The API documentation generation system provides:

### Rust-based Generation
- Custom documentation macros for API endpoints
- Utoipa integration for OpenAPI 3.0 spec
- Derive macros for schema generation
- Example code extraction from documentation comments

### Supported Output Formats
| Format | Extension | Use Case | Generated By |
|---------|-----------|-------------|--------------|
| Rustdoc HTML | .html | Developer reference | cargo doc |
| OpenAPI JSON | .json | API integration | utoipagen |
| OpenAPI YAML | .yaml | Human-readable spec | utoipagen |
| Markdown | .md | Documentation site | custom generator |
| TypeScript Types | .d.ts | Client SDK | custom generator |
| JSON Schema | .schema.json | Validation | schemars |

### API Surface Coverage
- REST API endpoints (server)
- WebSocket events (server)
- Tauri IPC commands (desktop)
- CLI commands (CLI)
- Web client API (web)

### Documentation Annotations
Required annotations for each public API:
- Description and summary
- Parameters with types and constraints
- Response schemas
- Error codes and descriptions
- Authentication requirements
- Rate limiting information
- Example requests and responses

## Compliance
- OpenAPI Specification 3.0.3
- IEEE 1016-2009: Recommended Practice for Software Design Descriptions
- TypeScript Documentation Standards
- Rust Documentation Guidelines
